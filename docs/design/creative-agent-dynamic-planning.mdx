# 通用创作 Agent 动态规划与画布协作需求设计

> 状态：待用户审阅，尚未实施。本文描述目标行为，不代表当前系统已经具备这些能力。
>
> 第一批实施进度：用户批准先做有限灵活性调整，已接入自定义问题字段、专业角色指导、动态计划和手动请求结果分析；继续保留现有完整方案与费用合同。原型视觉同步应用于原 Agent 卡片与输入框上方计划条。本文其余任务级 run、方案分层、统一批次执行等仍是后续设计，不应视为已实现。
>
> 本文是在第一期融合实现之上的调整设计。与旧设计有冲突时，以本文审阅通过的条目作为后续实施依据；未涉及的现有能力继续保留。配套旧原型仅供布局参考，不代表本方案的动态执行协议。

## 1. 产品目标

在当前画布的原 Agent 会话中，让用户通过自然语言、素材和问答卡片完成创作。Agent 根据任务扮演导演、设计师、电商美工、营销策划等专业角色，自主理解需求、读取画布、提出创意、规划步骤，并在授权范围内使用真实工具推进任务。

核心原则：创作路径由模型决定；真实能力、资源归属、执行结果、版本与费用授权由程序决定。

典型体验：

1. 用户描述目标，Agent 读取当前画布与已有资料。
2. 信息不足时按需提问；信息充分时直接给出创意方案。
3. 用户修改或确认方案，确认前不创建画布节点。
4. Agent 在批准范围内分批创建正式节点、整理布局与连线。
5. 涉及收费生成时展示真实费用，等待明确确认。
6. 工具完成后，Agent 根据结果决定继续、补问、修正或结束。
7. 计划、问答、批准与结果保存在原历史会话中，刷新后可核对恢复。

以上是可能经过的环节，不是每次都要执行的固定七步。普通咨询、纯文案、修改节点、制作整套作品采用不同路径。

## 2. 范围与非目标

### 2.1 本次包含

- 原在线 Agent 的动态规划和执行闭环。
- 专业角色提示词、按需加载已有 Skills 和可用插件能力。
- 模型自定义问题、选项和需求字段。
- 动态计划、可修改方案、按批次操作当前画布。
- 统一画布写入与收费授权检查。
- 失败反馈、有限自动修正、局部重做、历史及恢复。
- 短剧、设计、电商、营销及跨场景任务的共同运行机制。

### 2.2 本次不包含

- 不替换为 Harness，不建设完整服务端画布 MCP。
- 不新增独立智能创作聊天页面或第二套输入框。
- 不创建草稿节点；确认前的方案只存在于会话中。
- 首页接续继续暂缓，不扩大当前画布内的实施范围。
- 不建设通用角色/问卷低代码编辑器、公开插件市场或任意脚本执行平台。
- 不承诺模型能够临时发明可执行节点、编码安装插件或调用未注册工具。
- 不将浏览器关闭后的持续 Agent 思考纳入本期。已提交后端任务可以继续，后续编排需页面恢复。
- 不以本次改造直接承诺长剧、配音、字幕、剪辑合成全链路；具体交付受已接入能力约束。
- 不实现多用户同时编辑同一画布的完整协作协议。

## 4. 方案选择

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 只丰富场景提示词和选项 | 改动最少 | 字段限制、固定计划和执行分支仍然存在 | 不足以达到目标 |
| 原 Agent 负责决策，现有控制器负责受控执行 | 复用会话、画布、任务、审批与计费，逐步调整合同 | 要统一不同工具的执行边界 | 推荐 |
| 替换整套 Agent 框架与画布接入 | 可重新定义运行架构 | 迁移大，无法替代产品侧权限、账务和资源工作 | 本期不采用 |

## 5. 专业角色、Skills 与插件

### 5.1 角色配置从流程模板改为专业指导

建议角色配置保留：标识、展示名称、适用任务、专业目标、判断原则、质量检查点、参考案例和推荐 Skills。现有字段及问题参考作为建议，不作为唯一允许集合；节点规则中的真实业务约束保留为质量与素材要求。

| 角色 | 指导重点 | 不强制规定 |
| --- | --- | --- |
| 导演 | 人物动机、冲突、镜头叙事、节奏、连续性、现有剧本理解 | 题材、时长、角色数量、必须先做定妆图 |
| 视觉设计师 | 信息层级、构图、色彩、排版、品牌一致性 | 固定三种风格、固定海报结构 |
| 电商美工 | 商品真实性、购买动机、主图/详情/场景用途、卖点表达 | 必须做全套详情页、必须生成模特 |
| 营销策划 | 受众、传播目标、渠道、创意切入、行动引导 | 必须剧情化、必须制作视频 |

用户可以直接指定角色，也可以由 Agent 推荐；角色变化不清空已有需求。商品广告片允许组合电商、美术和导演指导。角色组合仍由同一个 Agent 完成，本期不引入多 Agent 调度。

### 5.2 按需加载

- 初始上下文提供精简角色和 Skill 目录，相关内容按需读取。
- 用户明确指定的角色/Skill 优先于系统推荐，仍不能绕过产品权限和收费规则。
- Skill 提供方法与规范；插件必须有实际注册的工具，才能增加执行能力。
- 工具目录声明输入、输出、读写影响、是否收费、可用条件及限制。
- 未提供抽帧、元素替换、合成等工具时，Agent 应指出缺口或提出可执行替代，不创建假功能节点。
- 现有原生节点与语义化工作流逐项审计后接入。第一批沿用已支持的文本、图片、视频；音频及其他专用节点按真实合同分步开放。

## 6. 上下文与需求记忆

### 6.1 每轮决策所需信息

1. 当前用户指令与最近对话。
2. 结构化需求摘要：目标、事实、偏好、限制、待解决问题、自主决定授权。
3. 当前画布 ID、真实节点、选区、关联资源与近期变化。
4. 当前任务、动态计划、方案版本和已批准范围。
5. 当前可用模型、工具、Skills 目录及所需能力详情。
6. 最新工具结果、失败原因、未完成操作和未消费报价。

原始历史完整保存，模型上下文采用摘要和按需读取，不要求把全部节点、全部 Skills、全部历史每轮重复发送。

### 6.2 需求字段

保留目标、时长、数量、比例、素材等可执行标准字段，允许模型补充如“结尾情绪”“品牌气质”“包装允许变化范围”等自定义字段。

每个字段保存稳定标识、显示名称、值、来源、对应消息/节点、确定程度与修订关系。程序生成可信标识；模型可以建议字段名称，但不能直接写执行权限、账务字段或服务端状态。

“模型建议”“用户确认”“用户授权 Agent 选择”分开保存。用户同意自主创意不代表授权虚构商品参数、随意增加费用或改变交付目标。

同义问题先关联已有字段，避免换一种表述重复问。确需修改已确认内容时，应说明冲突并记录新的用户依据。

## 7. 动态问答需求

### 7.1 何时提问

- 缺失信息会影响交付目标、事实准确性、关键创意选择或可执行性。
- 用户资料之间冲突，无法可靠判断。
- 现有能力不支持目标，需要选择替代方案。
- 当前结果引出了必须由用户决定的新问题。

不因场景模板存在字段就追问。可以合理建议的非关键偏好先给推荐，用户已授权自主选择时直接推进。

### 7.2 卡片交互

- 复用单选、多选、自由文本、素材选择和分页组件。
- 问题标题、说明、候选项由模型结合当前任务生成。
- 默认推荐每轮 1～3 题；允许确需一起决定时到 6 题。6 是防止长问卷的产品保护上限，不是要求凑满的题数。
- 选项可以随场景、画布素材和已知需求变化，提供自由补充。
- 支持“由你建议”；必需的真实商品事实、素材身份等不能以自主建议替代。
- 用户可以不点击卡片，直接在原输入框回答；Agent 解析后更新原问题状态并记录来源。
- 用户改变目标时旧问题标记为已替代，不自动删除历史答案。
- 有能力产生缩略图选择时可以复用真实素材预览；不能为展示选项偷偷生成收费图片。

### 7.3 验收重点

已知 10 秒、横屏时不再问时长与比例；指定完整剧本时先读剧本；商品图与价格已提供时直接规划；没有任何必要问题时不显示问答卡。

## 8. 动态计划与 Plan 式体验

界面只参考第一期原型的交互与布局。配色、字体、圆角、阴影和控件状态以系统当前主题及主题 token 为准，不复制原型主题，不单独建立 Agent 皮肤。

### 8.1 计划的用途

计划描述用户可以理解的工作目标，例如“分析商品”“确定视觉方向”“制作首张图”“完成系列图”，而不是暴露 API 调用列表。

只有多步骤任务才显示紧凑计划条，展开后查看当前、已完成、等待和跳过步骤。普通聊天、单次咨询不显示计划。无需新增独立模式页面；规划/执行状态在原会话中自然体现。

### 8.2 计划可调整

- Agent 可以新增、重排、拆分、跳过未执行步骤，并用一句话说明有业务意义的变化。
- 已执行记录不能通过重写计划抹掉；删除未开始步骤也保留修订记录。
- 步骤总数显示当前计划数量，变更后允许从 2/5 变成 2/6，附“新增结果检查”等说明。
- 步骤完成必须有依据：已展示方案、用户回答、成功工具结果或真实资源。
- 失败、部分成功、等待用户和等待后端任务分别展示，不能统称处理中。

### 8.3 推荐状态

计划步骤采用待开始、进行中、等待用户、等待任务、完成、失败、跳过。整体任务继续尽量复用现有 CreationStatus；计划步骤状态单独保存，避免将业务阶段膨胀成大量 API 状态。

计划允许动态调整，不代表审批状态可以由模型自行改变。

## 9. 创意方案与执行批次

### 9.1 创意方案

用户确认的内容包括：目标与交付物、核心创意、主要内容、沿用素材、关键规格、本阶段准备创建/修改的节点范围、明显能力缺口与自主选择范围。

方案格式按场景调整：导演可以给剧本与镜头设计；设计师可以给构图与视觉方向；电商美工可以给逐张用途与卖点。复用 Markdown 与方案卡片，不强制所有场景显示同样章节。

方案可分阶段批准，例如先批准剧本与角色方向，角色图产生后再讨论分镜。无需一次规划整部作品的全部技术细节。

### 9.2 执行批次

每批次保存目标步骤、方案版本、操作清单、受影响节点、素材依赖、解析后的生成规格、预期结果和执行状态。

创意方案无需包含每一个未来任务的完整供应商参数。但确认前应做能力可行性检查，不允许明知无法生成 60 秒视频却承诺直接交付。

批准后可以创建本阶段正式节点，并将未准备好的生成参数标记为待配置。只有参数完整、依赖就绪、报价批准的生成项才能执行。

模型选择所需能力及效果偏好；程序从当前目录解析真实候选。存在显著价格、质量或时长差异时交用户决定，不能悄悄替换已批准模型。

### 9.3 批准范围如何约束动态动作

当前后端批准绑定具体 ops，后续不能直接扩展成“这个 run 已批准，所以所有操作都允许”。建议将批准记录同时绑定：

- 方案版本和内容摘要。
- 允许创建的业务对象及数量、类型。
- 允许修改的已有节点 ID 与字段范围。
- 交付规格、关键素材与禁止修改项。
- 当前具体操作清单或由受限解析器生成的批次摘要。

后续批次必须由程序检查属于该范围；不能机械判断归属时重新展示批次确认，不让模型自行声称属于已批准范围。

首批实施优先采用可枚举的节点与字段清单。跨范围的大幅动态扩展需要新批准，避免过早建设复杂通用授权语言。

## 10. 确认与费用规则

| 操作 | 默认规则 |
| --- | --- |
| 读取当前画布、查看已授权素材、读取 Skill | 可自主进行 |
| 编写需求摘要、问题、方案、调整未执行计划 | 可进行文本推理，沿用当前文本计费方式 |
| 创建或修改方案中的正式节点 | 先批准方案或对应变更；批准范围内不逐节点重复问 |
| 用户明确要求移动/重命名指定节点 | 作为明确操作指令处理，遵循原工具确认偏好，不强制完整创意方案 |
| 改变数量、关键素材、时长、创意方向 | 对受影响部分重新确认 |
| 图片/视频及其他独立收费生成 | 真实报价批准后提交 |
| 删除或覆盖未在批准范围内的用户内容 | 展示目标与影响并确认 |
| 已消费生成的重做 | 新生成项与新报价，重新批准 |

“继续”“你决定”不构成费用批准。原确认开关可以控制普通工具操作体验，不能关闭创作方案与收费的硬门槛。

文本模型用于问答、方案编写和执行后判断，不等到最终确认才调用。方案确认与费用确认针对画布执行及具体生成消费；界面不能声称所有规划过程免费。

费用卡绑定真实模型、规格、数量、参考输入、请求摘要、报价版本与有效期。条件变化使相应批准失效，未受影响的已完成任务保留。

批量费用批准只覆盖卡片列出的有限请求。依赖前序产物、尚无法形成确定请求的后续生成，在依赖就绪后报价；本期不引入无限预算授权。

## 11. 统一画布执行入口

### 11.1 复用原画布能力

原读取、搜索、选区、节点、连线、布局与后置校验继续复用。模型通过已有适配器使用当前页面画布，本期无需改为服务端 MCP。

写操作执行前检查：当前画布匹配、真实资源归属、目标节点存在、批准范围、当前状态版本、输入合同和必要依赖。

执行后记录操作 ID、受影响节点、真实结果、变更摘要及错误。通过当前节点实际状态确认变更，不以模型回复作为完成依据。

### 11.2 防止不同工具绕过确认

原 `canvas_apply_ops` 中的生成操作、`canvas_run_generation`、生成工具的 `autoRun`、工作流自动运行与新创作控制器都必须进入同一执行检查。

普通画布写入与收费生成可以采用不同执行器，但批准范围和费用提交的验证不能只写在提示词或前端按钮里。后端对创作生成请求强制关联有效批准；具体路由合同在实施时覆盖所有现有入口。

### 11.3 手动编辑与并发

执行前重读受影响节点。用户修改过内容时保留用户版本，重新计算差异；改变已批准的生成输入时重新报价。

同一页面继续串行化 Agent 提交与原自动保存。执行租约防止同一任务被多个执行器同时推进，但不宣称解决整个画布跨设备协作。

## 12. 工具结果驱动的循环

决策循环为：读取任务上下文 → 模型决定下一步 → 程序校验 → 必要时等待用户 → 执行已授权动作 → 保存结果 → 回到模型。

到达问答、方案或费用等待点时暂停执行。同一批模型回复中出现等待交互后，不能继续执行夹带的写入或收费操作。

批次完成后，Agent 可以继续、补问、更新尚未执行步骤或建议重做。成功产物必须保留；后续推理失败不能把整个作品标记为不存在。

视觉检查仅在当前模型及输入协议真正支持读取产物时进行。视频审阅可能需要可用抽帧或视频理解工具，缺失时只报告状态、尺寸、时长等实际检查结果。

## 13. 失败与恢复

| 失败类型 | 处理 |
| --- | --- |
| 工具 JSON、引用或能力选择错误 | 将具体错误和失败参数作为工具结果返回，允许最多两次自动修正；不创建节点或生成媒体 |
| 信息缺失或目标冲突 | 改为提问，不反复生成无效方案 |
| 没有匹配模型或工具 | 展示能力差距，询问替代，禁止编造模型 ID |
| 报价过期或输入改变 | 作废相应未消费报价，重新报价并确认 |
| 网络中断且提交结果未知 | 查询原操作/提交 ID，不新建重复任务 |
| 媒体任务失败 | 保留成功项，说明失败项；新尝试按原账务事实判断并重新报价 |
| 用户暂停 | 停止后续编排，明确已提交任务可能仍在执行 |
| 页面关闭 | 保存等待位置；重新进入后核对后端任务，再由用户继续 |

自动纠正限于未执行参数，不自动重跑收费媒体。文本自动修正也消耗推理资源，达到限制后提供“修正方案”“修改要求”等操作，不无限循环。

## 14. 原会话与历史持久化

一个原聊天会话可以包含多个创作任务，一个任务可以跨多轮问答、多个方案版本和多个执行批次。不能继续把每条结构化消息都当成独立任务事实源。

原消息保存轻量内容快照与 task/run、interaction、proposal、step、batch 引用。服务端 run 保存当前执行事实；历史消息保留当时展示内容，不能全部渲染为最新方案。

需要持久化：

- 用户输入、结构化答案和自主选择授权。
- 需求摘要与来源、问题提交/替代状态。
- 计划版本、步骤修订与执行依据。
- 方案版本、用户批准范围、变更说明。
- 操作批次、报价与批准、任务与产物引用。
- 错误、自动纠正次数、暂停和恢复位置。

按用户 scope 隔离。UI 区分本地缓存与服务端保存；不将媒体大对象写进 localStorage，不在历史中保存密钥。

恢复先读服务端事实。已消费的批准不重放，旧方案确认按钮不可再次执行，失效报价不可继续扣费。旧单消息 run 历史只读展示；未完成旧任务按旧协议继续或明确结束后重新规划，不静默升级授权。

## 15. 概念数据合同

以下是职责草案，不代表立即增加同名数据库表：

| 对象 | 核心内容 | 权威来源 |
| --- | --- | --- |
| CreativeTask | 会话、画布、需求摘要、角色、当前计划和等待点 | 程序管理，绑定现有 run |
| Requirement | 字段、值、来源、确定程度、修订 | 模型提取，程序校验 |
| QuestionInteraction | 问题、候选项、关联字段、答案、版本 | 模型提问，程序分配标识并保存提交 |
| AgentPlan / PlanStep | 步骤、依赖、修订、状态、完成证据 | 模型建议结构，程序维护实际状态 |
| CreativeProposal | 内容、交付、规格、素材、拟操作范围 | 模型提案，用户批准 |
| ExecutionBatch | 具体操作、目标节点、前置条件、方案版本 | 程序校验和执行 |
| Approval | 批准类型、范围、版本、有效性 | 用户动作与服务端记录 |
| Submission / Task | 真实请求、报价、消费及结果 | 复用现有后端 |

标准字段和自定义需求分别存储；模型输出不直接合并进程序配置。权限与账务相关字段不接受模型赋值。

当前 CreationStatus 和 run.state 尽量复用。若批次幂等、批准范围需要索引与事务保证，则新增明确持久结构并同步数据库文档，不能只依靠无约束 JSON 提供安全保证。

## 17. 分期交付与人工验收

### A：动态规划与方案体验

交付角色指导、动态需求字段、动态计划、方案分层、原历史关联。未完成执行门槛改造前，不开放新的自主写入路径；不完整执行参数只用于规划展示。

验收：

- 完整需求直接出方案，不补无关问题。
- 用户通过普通输入框回答卡片，已回答字段不会再次提问。
- 一个商品广告需求可同时采用电商与导演方法。
- 问答数量和计划数量根据任务变化。
- 缺少后续媒体参数不阻塞创意方案阅读，无法完成的目标有明确说明。

### B：受控的动态画布执行闭环

交付任务级 run、执行批次、统一写入与费用门槛、结果回到模型、历史恢复。A+B 构成本次推荐最小完整交付。

验收：

- 方案确认前零新增节点、零媒体生成。
- 批准范围内分批创建节点，不每个节点重复确认。
- 从原工具、新创作入口及 autoRun 均不能绕过费用确认。
- 用户改动相关节点后，旧请求不能覆盖新内容或继续消费旧报价。
- 刷新、重复点击确认、网络超时均不重复创建或扣费。
- 成功与失败混合批次保留成功项，只处理失败项。

### C：产物驱动与专业能力增强

按实际可用视觉/视频能力接入检查，扩展更多已存在的节点工具与 Skills。缺失工具单独立项，不纳入基础闭环的隐含承诺。

验收：

- 根据真实产物提出下一步，而非固定跑完全部节点。
- 只修改指定海报或镜头，其他产物保留。
- 新增交付或重做产生新范围/费用确认。
- 无视觉读取能力时不输出虚构的画面检查结论。

本轮仅设计，不运行自动测试。实施后按用户要求进行实际使用调试；上线前涉及审批、账务、幂等和资源归属的验证需单独记录，不以浏览器截图代替这些行为的验证。

## 18. 三类端到端审阅示例

### 短剧

用户给出剧本和角色图。Agent 先读现有素材，提出镜头与节奏方案，不重复问题材和角色。用户批准本阶段后创建剧本文本与必要镜头节点，引用已有角色图。实际视频时长超出模型上限时先解释并询问拆段或缩短，不私自改变。生成费用确认后制作，产物完成后再决定是否需要下一镜头或局部重做。

### 电商

用户提供商品图并要求两张促销海报。Agent 确认真实促销信息与不可改包装范围，提出两种构图。用户批准后创建对应节点及素材引用，按真实模型与数量报价。第一张完成后，可在可用视觉能力下检查商品保留情况，继续第二张或提出调整；调整已批准请求时重新报价。

### 营销与普通设计

用户只要活动文案，Agent 直接给文字，不附带收费图片。用户随后要求海报时在同一任务或明确关联的新任务中扩展方案。用户仅要求将已有标题节点左移并改名时，走具体操作确认规则，不重新询问受众、风格、尺寸。

## 19. 建议审阅的产品决策

以下给出明确推荐默认值，审阅时可直接修改：

| 决策 | 推荐默认值 |
| --- | --- |
| 是否新增模式切换 | 不强制新增；原会话显示规划/执行状态 |
| 角色是否需要用户手动选 | 不需要，支持用户指定和模型按需组合 |
| 每轮问题数量 | 默认 1～3，确有需要最多 6，绝不凑题 |
| 参数错误自动修正 | 最多两次未执行参数纠正，不自动重跑媒体 |
| 画布节点何时创建 | 批准本阶段方案后创建正式节点 |
| 执行中是否可以改计划 | 可以；范围与费用变化单独重新确认 |
| 是否保留逐次媒体费用确认 | 保留，可批准明确列出的一个批次 |
| 本次最小交付 | A+B，C 按真实工具能力逐步加入 |
| 首页与跨画布 | 本次不扩大，当前画布内闭环优先 |

## 20. 交付判断

本次完成的判断不是“可以生成更多问题”，而是同一个 Agent 能结合真实画布与用户反馈，选择不同创作路径、维护动态计划、在批准范围内执行，并在结果、错误或需求变化后合理调整；同时，确认、费用、历史和恢复仍然可追溯。
