# 创作 Agent 第一期版本基线

用户已反馈基本流程验证通过。本基线保存当前可用实现，作为后续工作台扩展和问题定位的对照；这不代表全部模型协议、费用异常路径及部署环境均已通过专项验收。

## 本期实际范围

- 原画布在线助手支持动态问答、正式方案、按需执行计划、节点操作、分批报价、生成与结果接续，复用原会话、输入框、模型和技能。
- 普通画布工具按当前确认开关执行；模型承接当前任务授权，减少重复提问。结构化方案及费用仍以程序批准为准。
- 历史问答、方案和报价折叠；引用显示类型与标题；首页/创作页和画布在线、本机助手均采用回车发送、Shift+回车换行。
- 前端传输单份标准消息，后端路由后适配供应商；看图按需读取预览、原图或局部，派生图上传为资源，任务正文只保存资源引用。
- 上下文按预算保留当前要求和执行事实，旧会话按完整组省略。运行事实保存在创作 run/submission 中，历史消息保留展示快照。

## 收尾代码核对

| 边界 | 当前依据与结论 |
| --- | --- |
| 历史恢复 | `CanvasCreativeInteraction` 从原消息读取快照和 runId，controller 加载服务端 run；历史只读，恢复连接不自动批准 |
| 生成批准 | `ExecuteCreationSubmission` 在事务内检查批准、过期、撤销、方案范围及价格签名，再创建任务和额度预留；已有 TaskID 返回原任务 |
| 修改 | `proposal-invalidate` 撤销未提交生成的执行项；已提交任务不会由文字修改自动取消 |
| 资源 | 看图消息通过 `referenceImages` 提供资源清单；后端按用户读取 ready 资源，执行时还原；创作 run/submission 纳入资源删除引用检查 |
| 撤销 | 原画布撤销最多保留十批；用户后续修改导致快照不匹配时清空撤销链，避免覆盖手工编辑；不取消已提交生成或退费 |
| 隔离 | 浏览器缓存使用用户 scope，controller 检查账号与生命周期；服务端 run、submission、画布和资源按当前用户查询 |

以上为静态代码核对，不记为自动测试或浏览器全流程验证。本轮按用户要求未运行测试、类型检查、构建或收费模型请求。此前后端已通过开发启动编译，健康接口可用；它们仅证明启动入口可用。

## 保留的专项验收

- 四种模型协议的工具调用/结果及资源引用，尤其 Gemini 思考签名与协议插件。
- 刷新、切换会话、断线、暂停后恢复，以及修改前后旧报价不能再次消费。
- 原图复用、裁剪上传幂等、资源被引用时禁止删除、账号切换隔离。
- 明暗主题、窄屏、中文输入法、引用/技能候选与发送状态。
- PostgreSQL 迁移和部署验证。

## 版本与恢复边界

本次 Git 提交记录代码、设计和验收说明，不包含本地账号数据库、上传媒体、密钥、日志或构建产物。以该提交作为后续改动的对照点，必要时在独立检出中恢复代码，不覆盖正在使用的工作区。

本期数据库由 v8 增加到 v9。Git 回退不能恢复数据库、资源或账务；部署前应单独备份数据库和资源。数据库恢复或迁移回退需要另行核对影响，不随代码回退自动执行。

## 下一阶段

先设计首页进入画布时的同任务上下文接续、页面工具范围及角色/技能加载，再接通一个电商业务流程。当前仅首页发送快捷键统一，不宣称已实现首页到画布的同任务迁移。

本期不引入 Harness、完整服务端画布 MCP、动态插件节点注册、多人协作画布或完整长视频合成。这些能力继续作为独立阶段设计。
