# 会员等级与积分 实施方案（v5 · 全后台版）

日期：2026-10-10 修订（v5）。前提：**不支持在线充值，全部由后台操作**。管理员开通/升级/续费会员时，系统自动发放该等级积分并带到期时间；会员等级后台可配置。

> 2026-10-20 更新：会员月/季/年定价与在线购买已由 [membership-pricing-purchase-plan.md](./membership-pricing-purchase-plan.md) 实施；本文“二期预留”的在线支付购买已落地，后台人工开通仍保留。

v5 修订背景：官方 v1.6.3/v1.6.4 已合并（数据库 schema 升至 v49，运营数据新增用户余额/积分汇总），据此调整迁移编号、运营数据口径、台账枚举、幂等键设计与钱包布局。

## 一版范围

1. **会员等级后台配置**：等级名称、排序、启用、每月到账积分、存储总量、日上传、并发任务数（-1=无限）、签到积分覆盖。
2. **后台开通会员**：按用户选等级 + 周期（月数）开通；支持续费（顺延）、升级（换更高等级）、作废；全部带管理员备注与审计。降级直接拒绝。
3. **自动发放积分（会员积分池）**：开通/续费/每月锚点自动发放「每月到账积分」，到期时间 = 当前周期末；**当期未用完清零**（对齐价格表"每月到账、当月清零"），清零写台账可查。
4. **三项限制**：存储空间、并发任务、签到积分按等级生效。
5. **扣费双池**：生成扣费先扣会员积分池（未过期），不足再扣通用积分池（现状不动、永不过期）。
6. **用户侧**：钱包/我的页面显示会员等级、到期日、会员积分余额与到期时间（布局见 P4）。

二期预留（本期不做）：在线支付购买、折扣充值限购、模型专属积分卡、多档有效期（6 个月/2 年）→ 届时把会员池升级为通用批次池即可，字段设计已预留。

## 数据模型（迁移 v50）

**迁移编号动态取**：实施时以 `backend/internal/database/migrations.go` 的 `CurrentSchemaVersion + 1` 为准（上游发版会继续占用编号，v49 之后可能是 v50 也可能更大，不要照抄本文）。同步更新 `docs/content/docs/backend/backend-database.mdx`。

```
MembershipPlan（后台可配）
  id, name, level, enabled, sortOrder
  monthlyGrantMicrocredits      -- 每月到账积分
  activeTaskLimit               -- 0=默认全局值，-1=无限，>0=上限
  storageGB, dailyUploadMB      -- 0=默认全局值
  checkinBonusOverride          -- 0=用全局签到奖励

UserMembership
  id, userID, planID
  status                        -- active | cancelled
  periodStart, periodEnd        -- 当前周期（可跨多月）
  grantedMonths                 -- 已发放月数（对账用）
  note, createdAt
  -- partial unique index: userID where status=active

CreditAccount 增列（双池）
  membershipMicrocredits        -- 会员积分池余额
  membershipExpiresAt           -- 到期时间；归零/过期即不可用
```

**CreditLedgerType 新增枚举**（迁移内同步）：

- `membership_grant` — 会员积分发放（开通首月 / 锚点月度 / 续费首窗）
- `membership_upgrade_diff` — 升级补差
- `membership_expire_clear` — 过期清零

存量通用积分不动；免费用户两池行为与现状完全一致。

## 关键流程（已确认）

- **发放节奏（30 天锚点）**：开通立即发放首月额度，有效期 30 天；季/年度会员每 30 天自动发放一次（按开通日锚点，每日后台任务检查），每次发放有效期 30 天且不超过 periodEnd；周期末尾不足 30 天的按实际剩余天数有效，额度仍为整月。
- **幂等键**：锚点发放复用 `GrantCreditsOnce`（`repository/finance.go`）的 referenceKey 去重，键格式 `membership-grant:{membershipID}:{windowIndex}`；升级补差 `membership-upgrade:{membershipID}:{periodEnd}`。每日任务重跑不会重复发放。
- **升级（立即生效）**：只补积分——补差 = 新等级月额度 − 旧等级月额度，**整额补进会员池，不按剩余天数折算**（不管已用多少天、何时首次开通）；补差积分有效期跟随当前会员池到期时间。降级在 **service 层**拒绝（不放在 handler，未来开放在线购买时同一约束自动生效）。
- **续费**：periodEnd 顺延 N 月，新周期首个 30 天窗口按（新）等级发放。
- **扣费**：扣费/预留/退款路径按「会员池优先 → 通用池」拆分；会员池过期（now > membershipExpiresAt）视为 0 并触发清零入账。
- **过期清零**：每日任务扫描 membershipExpiresAt < now 且余额 > 0 的账户，清零并写 `membership_expire_clear` 台账。每日任务挂现有 worker/调度模式（`internal/platform`、`task_worker.go` 同款）。
- **签到积分**：按等级**覆盖**全局值（0 = 用全局默认）。接入点：`EffectiveMembership` 解析后替换 `CreditPolicy.CheckinBonusMicrocredits`（`credit_policy.go`），发放仍走 `GrantCreditsOnce` 进**通用池**——签到不进会员池、不受清零影响。

## 运营数据口径（v5 新增，2026-10-10 确认）

官方 v1.6.4 的管理端运营数据（全平台用户余额、用户积分汇总、累计充值）与双池的关系：

- **汇总口径 = 两池之和**（会员池 + 通用池）；列表/详情**分列**「会员积分余额（含到期时间）」和「通用积分余额」。
- 累计充值、签到积分汇总不变（都发生在通用池）。
- 过期清零只影响会员池余额，不产生通用池流水，运营趋势不受干扰。

## 钱包布局（v5 新增，P4 按此实现）

用户侧钱包/我的页面同时存在三块内容，布局定为：

1. **通用积分余额**——现状展示不动（充值、签到、初始赠送都在这里）。
2. **会员卡片区**——等级名、到期日、会员积分余额 + 「x 月 x 日前有效」；会员过期或无会员时不显示余额、只显示开通引导（指向联系管理员，一期无自助购买）。
3. **充值入口**——现状不动（积分充值支付插件），保持独立入口，不与会员卡片区混排。

扣费提示文案统一为「优先使用会员积分」；会员积分不足以覆盖时提示明细拆分（会员池扣 X、通用池扣 Y）。

## 已确认决策

### 2026-10-09

1. 发放节奏：开通立即发放首月（30 天有效）；季/年度每 30 天自动发放一次，当期清零。
2. 升级立即生效、只补积分：补差 = 新旧等级月额度之差，整额补进会员池（不按剩余天数折算），有效期跟随当前会员池；**暂不支持降级**（后台拒绝换到更低等级）。
3. 签到积分按等级覆盖全局值。
4. 无在线支付，全部后台操作；开通即发首月。

### 2026-10-10（v5）

5. 运营数据汇总口径 = 两池之和，列表分列会员池/通用池余额；累计充值与签到汇总不变。
6. 签到积分发放进通用池，不受会员池清零影响。
7. 钱包页面三块布局：通用余额（不动）/ 会员卡片区（等级+到期+会员余额）/ 充值入口（不动）。
