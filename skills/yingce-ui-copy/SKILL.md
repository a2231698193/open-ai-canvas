# 影策界面文案

界面文字只有一个任务：**让用户知道下一步做什么、做了会怎样**。能用控件本身说清楚的，就不要再写一句话。

## 1. 总原则

1. **少**：每个区块最多一句说明；一句话不超过 30 个字为宜。删掉后用户仍能完成任务的文字，就删掉。
2. **不重复**：标题、标签、说明、占位符、Tooltip 不说同一件事。同一信息只出现一次。
3. **具体**：说具体的东西（「需要商品主图，建议补充细节、包装」），不说空话（「请上传相关素材以获得更好效果」）。
4. **平实**：不用营销腔、不用感叹号、不用 emoji、不用「✨智能」「一键搞定」「极致」「赋能」。
5. **一致**：同一概念全站一个词。用词表见 §7。
6. **数字带单位、中间留空格**：`3 张`、`12 GB`、`1 / 3 已开放`；用等宽数字。
7. **中文标点**：句中用中文逗号句号；中英混排时英文和数字两侧不手动加空格（`text-autospace` 自动处理），但数字与中文单位之间留空格。

## 2. 各位置怎么写

### 页面标题
- 名词短语，2–8 字：「电商 Agent 配置」「知识与技能」「方案与作品」。
- 不加「管理」「中心」「平台」凑字，除非就是这个意思。

### 页面 / 区块说明（标题下一行）
- 一句话说**这里决定什么**或**为什么要填**：「决定电商 Agent 是否对用户开放、各阶段使用哪个模型」「比例与清晰度随模型变化」。
- 不写「在这里你可以……」「本页面用于……」「请填写以下信息」。

### 区块标题
- 动词或名词短语，2–6 字，按用户做事的顺序：「做什么」「商品素材」「画面描述」「投放平台」「模型与规格」。

### 字段标签
- 名词，2–6 字：「商品名称」「参考方式」「单次回复上限」。
- 必填用控件状态表达，不在标签后写「（必填）」，除非表单里必填和选填混杂且难以区分。
- 单位、范围写进说明行：「Token，128–4096」，不写进标签。

### 占位符
- 给一个**真实例子**：「例如：便携式香薰机」「例如：美国、日本」。
- 不把说明写进占位符（用户一输入就看不到了）。

### 按钮
- 动词开头，2–6 字，说清结果：「生成」「保存创作助手」「去功能开放调整」「按方案生成 9 张图片」。
- 主按钮写这一步的结果；有数量就带数量。
- 不写「确定」「提交」「OK」，除非是通用确认弹窗。
- 危险按钮写对象：「删除项目」「移除这张」，不写「删除」两个字孤零零。

### 开关
- 标签写「启用 X」或直接写能力名；下面一行写**关闭后会怎样**：「关闭后不显示入口，也不会发起模型调用」。

### 空态
- 一行标题说这里会放什么，一行说明说下一步具体动作：
  - 标题「这一轮的方案和作品会出现在这里」
  - 说明「先在右侧添加商品主图，作品会显示在这里」
- 根据状态变化：未开放 → 缺素材 → 缺描述 → 可以生成，各写一句（见 `web/src/pages/ecommerce/index.tsx` 的 `nextStep`）。
- 不写「暂无数据」「空空如也」「快去创建吧！」。

### 加载与进度
- 说正在做什么：「正在整理视觉方向…」「正在恢复商品创作…」「排队中」「生成中」。
- 用省略号「…」（一个字符），不用「...」。

### 报错
- 结构：**发生了什么 + 原因（如果知道）+ 用户能做什么**。
  - 「图片导出未完成：下载连接暂时中断。可以重新点击导出。」
  - 「启用前请先选择对话模型」
- 不写「操作失败」「系统错误」「未知错误，请联系管理员」作为全部内容。
- 不把后端英文错误码或堆栈直接给用户；原因文字来自 `ApiError.message`，类型判断用 `reason` / `code`。
- 付费相关要说清是否扣费：「重新获取不会重新生成，也不会重复扣费」。

### 确认弹窗
- 标题是问题：「删除这 3 个项目？」
- 正文写后果和不会发生的事：「项目内的画布和作品一起删除，素材库里的文件保留。」
- 按钮：取消 / 危险动作的具体名称。

### Toast（`App.useApp().message`）
- 一句话，说结果和生效范围：「创作助手设置已保存，立即生效」「已复制」。
- 成功操作已经在界面上可见时，不再弹成功 toast。

### Tooltip
- 只给**图标按钮**和**禁用原因**用；4–15 字：「历史项目」「新建商品创作」「电商视频暂未开放」。
- 不给已有文字标签的按钮再加一句复述的 Tooltip。

## 3. 反例 → 改法（真实出现过）

| 反例 | 问题 | 改法 |
| --- | --- | --- |
| 顶部大字「COMMERCE STUDIO 让商品的价值，被一眼看见。以真实商品为起点，让每一张图都有清晰的表达。」 | 营销文案占首屏，不帮用户做事 | 删除 |
| 区块标题「需要借鉴的图片」+ 字段「参考方式」+ 说明「使用上方“自己的商品图”自主策划，无需上传借鉴图片。」+ 另一句「根据商品图和已确认资料…」 | 四处说同一件事 | 字段「参考方式」+ 一句说明 |
| 「这次想呈现什么？选择商品成品，再补充需要的素材。简单图片可直接生成；详情套图可在检查方案后生成。」 | 三句话解释一个选择 | 区块标题「做什么」+ 选中场景后显示一句该场景的产出说明 |
| 每个参数按钮都挂一个 Tooltip：「调整文字、模特、画幅与清晰度。」 | 按钮本身已经写着「图片参数」 | 去掉 Tooltip，参数直接平铺在面板里 |
| 空态「选好场景与商品素材后，作品会显示在这里。可以从右侧创作面板开始，生成图片、套图方案或商品视频。」 | 啰嗦且没有按状态给下一步 | 「这一轮的方案和作品会出现在这里」+ 按状态的一句下一步 |
| 「小夜会调整对应的画面结构」 | 拟人化角色名混入功能说明，用户不知道“小夜”是谁 | 直接说功能：「切换后调整画面结构」或不写 |
| 「操作失败，请稍后重试」 | 没有原因、没有对象 | 「保存失败：网络中断。修改已保留，可以再次保存。」 |

## 4. 语气

- 第二人称省略主语：「先添加商品图」，不写「您需要先添加商品图」。不用「您」「亲」。
- 系统不自称「我」「小夜」，不卖萌。
- 不承诺做不到的事：不写「保证通过平台审核」「效果最佳」。
- 不确定的写清楚边界：「详细规则待官方后台核实」。

## 5. 长说明放哪里

- 平台规则、计费说明、免责声明：收进 `<details>`（默认折叠）或文档链接。
- 技术细节（模型 ID、接口名、任务 ID）：只放在「查看详情」、后台或 `title` 属性里，不放在主界面。

## 6. 后台文案

- 管理员需要准确，不需要客气：「已保存，新提交的任务立即生效」「读取失败：<原因>」。
- 统计数字旁写清口径：「有效 · 已审核且未过期」。
- 改名旧功能时，在说明里写一次新旧对应（「原小夜设置」），之后不再提旧名。

## 7. 用词表

| 用 | 不用 |
| --- | --- |
| 作品 | 产物、结果图、输出物 |
| 生成 | 创作（作为按钮）、提交、运行 |
| 素材 | 资源（面向用户时）、文件 |
| 商品图 | 产品图、主体图（同一页面里只用一个） |
| 模型 | 引擎、大模型（面向用户时） |
| 积分 | 点数、额度（计费语境） |
| 项目 / 画布 | 工程、画板 |
| 重新生成（会扣费） | 重试（只用于「失败后再提交同一任务」） |
| 重新获取（不扣费） | 刷新、重新加载 |
| 创作助手 | 小夜（新界面不再使用角色名） |
| 电商 Agent | 电商助手、电商机器人 |
