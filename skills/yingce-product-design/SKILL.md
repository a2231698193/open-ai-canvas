# 影策产品设计

影策是面向 AI 影视与短剧创作的工作台。用户来这里是为了**做出作品**，不是为了操作功能。页面好不好，先看用户能不能在 5 秒内回答三个问题：

1. 这个页面是干什么的？
2. 我现在该做哪一步？
3. 做完了结果在哪里？

答不上来的页面，样式再精致也是失败的。

## 1. 动手前必须写下来的四件事

在写任何 JSX 之前，先在脑子里（或回复里）写清楚下面四项。写不出来就去读调用方、路由和后端接口，直到写得出来。

| 项 | 要回答的问题 | 例子（`/ecommerce` 电商创作页） |
| --- | --- | --- |
| 用户与目标 | 谁来，想带走什么 | 卖家来，要一件商品的一整套上架图 |
| 主路径 | 从进入到拿到结果的最短步骤，3–6 步 | 选场景 → 加商品图 → 写描述 → 确认规格 → 生成 → 在左侧看作品 |
| 结果落点 | 结果出现在哪、什么时候出现 | 提交后左侧立即出现占位卡，完成后原位变成作品 |
| 不在主路径上的东西 | 哪些是进阶、低频、只读、管理员才需要的 | 参考方式、文案风格六项、平台规则详情、历史项目 |

主路径上的东西放在显眼位置、按步骤顺序排列；不在主路径上的东西折叠、收进弹窗、移到次要入口或干脆不放。

## 2. 组织页面的方法

### 2.1 按任务分区，不按数据结构分区

- 错：一个表单把后端字段从上到下全列出来（`productName`、`referenceMode`、`creativeOptions.textMode`……）。
- 对：按用户做事的顺序分区，每区一个动词或名词短语标题——「做什么」「商品素材」「画面描述」「投放平台」「模型与规格」「文案与视觉」。区块标题后面跟一句**这区为什么要填**的短说明，而不是“请填写以下信息”。

### 2.2 一个页面一个主操作

- 每个视图只有一个 `type="primary"` 按钮，它就是主路径的终点（「生成」「保存」「确认并生成」）。
- 次要动作用默认按钮或文字按钮；管理动作（删除、导出、历史）用图标按钮或「更多」菜单。
- 主操作位置固定：创作面板放底部固定栏；设置分区放分区底栏右侧；弹窗放右下角。

### 2.3 输入在一侧，结果在另一侧

创作类页面统一采用**创作面板 + 结果区**两栏（参考 `/toolbox/image`、`/toolbox/video`、`/ecommerce`）：

- 创作面板固定宽度（380–420px）、满高、内部滚动、底部固定提交栏（报价 + 主操作）。
- 结果区占剩余宽度，顶部是标题 + 计数 + 筛选 + 导出，主体是批次/作品网格。
- 流程中的中间产物（已发送的需求、方向选择、方案审阅、进度、错误）出现在**结果区顶部**，不要塞进输入面板，也不要做成悬浮气泡。
- 窄屏（≤760px）用分段切换「创作 / 作品」，不要上下堆叠两个满高区域。

### 2.4 渐进披露

- 默认只露出完成主路径必需的控件。进阶参数收在区块内（选择框、可展开说明）或弹窗。
- 由选择驱动后续内容：选了场景才出现该场景需要的素材说明和描述短语；选了“参考风格”才出现借鉴图上传区。不要一次把所有模式的控件都画出来再置灰。
- 能由系统决定的不让用户决定（例如分析模型由后台固定，前台不展示；比例列表按模型能力生成）。

### 2.5 状态必须有落点

每个异步操作都要回答：进行中在哪显示、成功后变成什么、失败在哪说、怎么重试。

- 提交后立即在结果区出现占位（排队 / 生成中），不要等接口返回再出现。
- 失败就地说明：哪一张、为什么、能不能只重试这一张。不要只弹一个 toast 然后什么都不剩。
- 区分「本地缓存成功」和「服务端已保存」，不要把降级当成功。
- 空态告诉用户下一步具体做什么（「先在右侧添加商品主图」），不是泛泛的「暂无数据」。

### 2.6 一个概念一个名字，一个功能一个入口

- 同一件事在全站只用一个词（「作品」不要一会儿叫「结果」一会儿叫「产物」）。
- 同一个设置只在一个地方修改；其他地方只读展示并提供跳转（例如电商 Agent 配置页的「开放状态」只汇总开关，修改跳「功能开放」）。
- 两个页面能力重叠时，要能一句话说出区别（工具箱「图片生成」= 一次出几张；电商 Agent = 一件商品的一整套上架图），并在两边互相引导。

## 3. 信息层级

每个视图的视觉权重从高到低只能有三层，多了就是乱：

1. **主角**：结果区的作品 / 当前正在编辑的内容 / 表格数据。
2. **主路径控件**：分区标题、主输入框、主操作按钮。
3. **辅助信息**：说明、元信息、计数、状态标签。

具体手段（细节见 `yingce-ui-system`）：
- 层级靠字号档位 + 文字颜色（ink / muted / soft）+ 表面明度拉开，不靠加粗、加框、加色块。
- 同一视图里，标题最多两档（页面标题 22px、区块标题 13–16px）。
- 说明文字统一 12px、`--user-ink-soft`/`--user-ink-muted`，一个区块最多一句。

## 4. 反面清单：GPT 式“平铺功能页”

出现下面任何一条，就是在堆功能而不是做产品，必须改：

| 症状 | 为什么错 | 改法 |
| --- | --- | --- |
| 页面顶部一个大横幅/宣传语（“让商品的价值，被一眼看见”） | 工作台不是营销页，占首屏却不帮用户做事 | 删掉；需要标题就用页面标题 + 一句说明 |
| 卡片里套卡片、边框里套边框 | 层级靠线和框硬撑，视觉噪音大 | 一个面板只有一层表面，分区用分隔线和间距 |
| 每个控件旁边一句说明，说明还在重复标签 | 文字比功能多，用户不读 | 每区最多一句，只写标签说不清的事 |
| 同一信息说两遍（区块标题“需要借鉴的图片”+ 字段名“参考方式”+ 说明“使用上方…”） | 重复 = 噪音 | 留一处，删其余 |
| 所有模式的控件同时可见，再用 disabled 置灰 | 用户要自己判断哪些和自己有关 | 由选择驱动显示 |
| 输入框下面挂一排 6–8 个同样大小的胶囊按钮，每个点开一个悬浮气泡 | 没有主次，参数藏在浮层里看不到当前值 | 参数直接在面板分区里展示当前值；只有真正的大选择（平台、物料）才用弹窗 |
| 右侧悬浮提示框式面板、左侧却是内容 | 布局语义混乱 | 面板满高贴边、和结果区同一套表面 |
| 筛选按钮是装饰（点了没反应） | 假控件比没有更糟 | 要么接上逻辑，要么不放 |
| 字体大小四五种、粗细三四种混用 | 没有排版系统 | 只用 token 五档字号和 400/500/600 |
| 自己手写按钮、开关、下拉、弹窗样式 | 和全站不一致，暗色常出问题 | 用 `yingce-ui-system` §8 的组件 |
| 用 emoji 当图标、用感叹号、写“✨ 智能”“一键搞定” | 廉价感 | lucide 图标，平实中文 |
| 空态写“暂无数据” | 没告诉下一步 | 写下一步具体动作 |
| 一个页面三个蓝色主按钮 | 主次不分 | 一个主操作，其余次要 |

## 5. 设计决策的默认答案

拿不准时用这些默认值，除非有明确理由：

- 列表 / 内容库：页头（标题 + 计数 + 命令组）→ 工具栏（搜索 + 筛选 + 视图）→ 网格；见 `references/patterns.md` §2。
- 设置页：一列分区卡片，每区「标题 + 一句说明 + 状态徽章」→ 字段 → 底栏（保存状态 + 保存按钮）；见 §3。
- 选择项 ≤ 6 个且需要一眼对比：平铺成按钮组 / 分段；> 6 个或需要说明：选择框或弹窗。
- 数量：步进器（−  N 张  +），不要滑块。
- 布尔：Switch，标签写“启用 X”，下面一行写关掉后会怎样。
- 危险操作：原位确认，写清后果；真实请求完成前保持 loading，失败保留面板。
- 时间：`RelativeTime`；数字带单位且中间留空格（`3 张`、`12 GB`）。

## 6. 后台（/admin）的产品设计

后台的用户是管理员，目标是**确认状态、改对配置、处理异常**。

- 菜单按业务域分组，组内条目是名词短语（「电商 Agent 配置」「知识与技能」），不用「XX 管理」「XX 设置」泛词堆叠。同一业务的页面放在同一组，不要一半在「系统设置」一半在业务组。
- 配置页顶部先给**状态汇总**（开没开、哪里阻塞、几项已配置），再给可编辑分区。
- 一个开关只在一处可改；其他页面只读汇总 + 「去 XX 调整」按钮。
- 统计数字用 `AdminStatTile`，不要一行 `Typography.Text` 罗列「知识条目 79475 有效 79474 待审核 0…」。
- 长表单按「开放与外观 / 模型与计费 / 内容与知识」这类业务分组，每组之间分隔线，不嵌套卡片。
- 保存：显示「有未保存的修改 / 已保存」，提供撤销；保存成功 toast 一句话说明生效范围（「立即生效」「新提交的任务生效」）。

## 7. 改造现有页面的步骤

1. 打开真实页面截图（亮/暗、1440 与 390 宽），列出：主路径是什么、哪些控件不在主路径上、哪些文字重复、哪些层级靠边框撑。
2. 写下 §1 的四件事。
3. 画出新的分区顺序（只用文字列出即可），确认每区只有一个目的。
4. 保留所有业务逻辑与测试契约（`aria-label`、测试用的 class、接口参数），只重排结构和样式；必须删除的旧结构要同步改测试。
5. 用 `yingce-ui-system` 的组件和 token 实现。
6. 按 `yingce-page-review` 截图自检。
