# 影策页面交付自检

**静态阅读代码不算验证。** 交付 UI 改动前，至少在真实路由上看过一次亮色和暗色截图。不能截图时要明确写「未在浏览器验证」，不要把类型检查通过写成页面没问题。

## 1. 验证环境

- 不要动用户正在用的开发数据。宿主机开发用 `CANVAS_BACKEND_DATA_DIR=../.local/project-workbench-debug`；需要单独账号时，起一个临时数据目录的后端（例如 `/tmp/<name>-data`，另开端口），首个注册用户即管理员，再按需打开功能开关（`PATCH /api/admin/settings/features`）。
- 前端：`cd web && VITE_API_PROXY_TARGET=http://127.0.0.1:<后端端口> ./node_modules/.bin/vite --port <端口> --strictPort`。
- 截图：无头 Chrome + CDP（`--headless=new --remote-debugging-port`），登录后 `Page.navigate` 到真实路由；切暗色用 `document.documentElement.classList.toggle("dark", true)`。需要模型列表时可拦截 `/api/model-catalog` 与 `/api/model-catalog/quote` 返回演示数据，但**不要提交真实生成任务**。
- 不得为了验收另做独立 HTML 页面；独立页面截图不算真实页面通过。
- 验证完停掉自己启动的进程。

## 2. 必截的画面

| 画面 | 尺寸 |
| --- | --- |
| 默认状态（亮） | 1440×900 |
| 默认状态（暗） | 1440×900 |
| 主要弹窗 / 浮层打开时（暗） | 1440×900 |
| 面板滚动到底 | 1440×900 |
| 窄桌面 | 1100×760 |
| 手机 | 390×844 @2x |
| 有数据的状态（进行中 / 完成 / 失败各一个，必要时拦截接口造数据） | 1440×900 |

看截图时**真的去看**：文字是否被截断、两个元素是否重叠、悬浮元素是否盖住主操作、某个控件的名称是否消失（例如图标容器把文字挤成 0 宽）。发现异常用 `getComputedStyle` 读实际样式定位是哪条旧规则在覆盖。

## 3. 检查清单

### 产品
- [ ] 5 秒内能说出页面是干什么的、下一步做什么、结果在哪里。
- [ ] 主路径控件按做事顺序排列；不在主路径上的控件已折叠或移走。
- [ ] 每个视图只有一个主按钮，位置固定（面板底栏 / 分区底栏右侧 / 弹窗右下）。
- [ ] 提交后结果区立即出现占位；失败就地说明并能单项重试。
- [ ] 空态按当前状态给出具体的下一步。
- [ ] 筛选、排序、导出等控件都真的能用。
- [ ] 同一设置只在一个地方可改；只读汇总处有跳转。

### 版式
- [ ] 一个面板只有一层表面，没有卡片套卡片、边框套边框。
- [ ] 区块之间用分隔线和间距，不用嵌套底色块。
- [ ] 字号只用 token 档位，一个视图 ≤ 4 档；字重只用 400 / 500 / 600。
- [ ] 间距、圆角都在允许值内；嵌套圆角同心。
- [ ] 左侧没有竖向强调条。
- [ ] 媒体有固定比例，加载前后不跳。
- [ ] 窄屏不溢出、不重叠；≤ 760px 两栏改为切换。

### 配色
- [ ] 亮 / 暗都能看出 页面 → 面板 → 内凹 → hover 的层级。
- [ ] 主操作色只出现在主按钮和焦点环；普通选中用 `--control-selected-*`。
- [ ] 没有渐变、发光、彩色投影；暗色卡片无阴影。
- [ ] 每处颜色都能说出含义；去色后主操作、选中、失败仍可分辨。
- [ ] 代码里没有新增十六进制 / rgb 字面值（媒体浮层 token 除外）。

### 组件
- [ ] 按钮、开关、分段、下拉、弹窗、Tooltip、空态都来自现有组件（见 `skills/yingce-ui-system/references/components.md`）。
- [ ] 没有在页面 CSS 里改按钮高度、圆角、颜色、阴影。
- [ ] 没有全局 `.ant-*` 覆盖；新覆盖都有组件作用域。
- [ ] 没有用 antd `Empty`、静态 `Modal.confirm`、静态 `message`、直接 antd `Tooltip`。

### 文案
- [ ] 每个区块最多一句说明，且不和标题 / 标签重复。
- [ ] 按钮是动词短语、说清结果；危险按钮写对象。
- [ ] 报错有原因和下一步；付费相关写清是否扣费。
- [ ] 没有营销腔、感叹号、emoji、拟人角色名。
- [ ] 数字带单位且留空格。

### 交互与可访问性
- [ ] 键盘 Tab 能到所有控件，`:focus-visible` 焦点环清晰；鼠标点击不留焦点框。
- [ ] 图标按钮有 `aria-label` 或 sr-only 文字；持久切换用 `aria-pressed`。
- [ ] 进度用 `role="status"`，错误用 `role="alert"`。
- [ ] Escape 能关闭弹窗与浮层；弹窗关闭后焦点回到触发按钮。
- [ ] `prefers-reduced-motion` 下没有位移和缩放。
- [ ] 禁用控件悬停能看到原因。

## 4. 命令

```bash
cd web
bun run typecheck
bun run lint                 # 只拦 antd Empty 与静态 Modal.confirm，不是风格检查
bun test <相关测试>           # 改了页面结构要同步更新页面测试里的选择器
./node_modules/.bin/prettier --write <改动的文件>
```

推送前在仓库根目录运行 `bun scripts/verify-before-push.mjs`（见 `AGENTS.md` §8）。

## 5. 交付说明怎么写

- 写看过哪些截图（主题、尺寸、状态），发现并修了什么。
- 写没验证的部分（例如「未用真实账号提交生成任务」「未在 Safari 检查」），不要省略。
- 截图放在 `.local/cache/` 下，不要提交进仓库；PR 需要的截图放 `.github/pr-screenshots/<主题>/`。
